# Build and release

Bookfetch has one production identity: name **Bookfetch**, iOS bundle id and Android package
**`com.nickpopov.bookfetch`**, Apple team `35G54C9LN9`. There are no staging or development variants.
Store builds come from fastlane on the build Mac (local Xcode and Gradle, Continuous Native Generation).
`ios/` and `android/` are generated by `expo prebuild --clean` inside the lanes and are never committed.

## Tooling

- Ruby with Bundler. The parent machine uses Homebrew Ruby (`/opt/homebrew/opt/ruby/bin`). `Gemfile` pins
  `fastlane ~> 2.240`, and `Gemfile.lock` is committed. Run `bundle install` once, then run lanes as
  `bundle exec fastlane <platform> <lane>`.
- Node for `npx expo prebuild` and `scripts/bump-version.mjs`.
- Files: `fastlane/Fastfile` (lanes), `fastlane/Appfile` (identity, team from `APPLE_TEAM_ID`),
  `fastlane/release_checks.rb` (pure checks with no fastlane dependency), `fastlane/test/release_checks_test.rb`.
- Tests for the checks: `/opt/homebrew/opt/ruby/bin/ruby fastlane/test/release_checks_test.rb` (minitest, no gems needed).

## Environment

Fastlane loads `.env` from the repository root. A variable already set in the shell wins. You can also load
an extra `.env.<name>` with `--env <name>`. `.env.example` lists every name without values. `.env` and
`.env.*` are git-ignored, except `.env.example`.

| Variable                                                                                                                | Used by                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `APPLE_TEAM_ID`                                                                                                         | `ios build`/`ios beta` (export `teamID`), Appfile, carried into `expo prebuild`                                      |
| `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_PATH`                                                                           | `ios beta`: TestFlight lookup and upload. Also passed to `xcodebuild -authenticationKey*` for automatic provisioning |
| `BOOKFETCH_BUILD_KEYCHAIN`, `BOOKFETCH_BUILD_KEYCHAIN_PASSWORD_FILE`                                                    | optional headless signing (below)                                                                                    |
| `PLAY_JSON_KEY_PATH`                                                                                                    | `android beta`: Google Play service account JSON                                                                     |
| `ANDROID_UPLOAD_STORE_FILE`, `ANDROID_UPLOAD_STORE_PASSWORD`, `ANDROID_UPLOAD_KEY_ALIAS`, `ANDROID_UPLOAD_KEY_PASSWORD` | `android build`/`beta`/`apk`: the upload keystore                                                                    |

The keys (`.p8`, Play JSON, upload keystore, keychain password file) live **outside the repo on the build Mac**.
Paths may be absolute or relative to the repository root. No value appears in a tracked file.

The lanes map the Android upload variables to Gradle properties `BOOKFETCH_UPLOAD_STORE_FILE`,
`BOOKFETCH_UPLOAD_STORE_PASSWORD`, `BOOKFETCH_UPLOAD_KEY_ALIAS` and `BOOKFETCH_UPLOAD_KEY_PASSWORD`, through
`ORG_GRADLE_PROJECT_*` for the Gradle run only. `plugins/with-android-signing.js` adds an `upload` signing config
that reads them, and signs `release` with it, falling back to the debug key when the properties are missing.
The app config must list `./plugins/with-android-signing.js` in `plugins`.

## Lanes

| Command                                               | What it does                                                                                                                                                                                                                     |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bundle exec fastlane ios build`                      | Prebuild iOS, archive the `Bookfetch` scheme (Release), export `build/ios/Bookfetch.ipa` for the App Store, run the ipa check                                                                                                    |
| `bundle exec fastlane ios beta`                       | Build number = max(version.json, latest TestFlight + 1), then `ios build`, then upload to TestFlight (does not wait for processing)                                                                                              |
| `bundle exec fastlane android build`                  | Prebuild Android, `bundleRelease`, copy to `build/android/com.nickpopov.bookfetch-<version>-<build>.aab`, run the manifest check. Without upload variables it is signed with the debug key (not uploadable)                      |
| `bundle exec fastlane android beta [status:draft]`    | Version code = max(version.json, highest on any Play track + 1), build signed with the upload key, upload to the **internal** track with `release_status` = `status` (default `draft`; also `completed`, `inProgress`, `halted`) |
| `bundle exec fastlane android apk`                    | On request only: `assembleRelease` signed with the upload key to `build/android/…apk`. Uploads nothing and keeps the build number                                                                                                |
| `bundle exec fastlane bump [version:1.0.1] [build:5]` | Runs `scripts/bump-version.mjs`                                                                                                                                                                                                  |

Each build lane first runs `ensure_no_other_build`: the 8 GB build Mac never runs `xcodebuild` and a Gradle
daemon together. The ipa export runs with `/usr/bin` first on `PATH`, because Homebrew's rsync breaks
`xcodebuild -exportArchive` ("Copy failed").

### iOS signing

- Default: automatic signing with `-allowProvisioningUpdates`, using the App Store Connect API key when it is set.
- Headless (SSH session with a locked login keychain): set `BOOKFETCH_BUILD_KEYCHAIN` to a keychain that holds
  the Apple Distribution identity, and `BOOKFETCH_BUILD_KEYCHAIN_PASSWORD_FILE` to a file with its password. The
  lane unlocks that keychain, makes it the only one in the user search list during the build, and restores the
  list afterwards. The export then uses manual signing with the profile
  **`Bookfetch App Store com.nickpopov.bookfetch`**, installed in `~/Library/MobileDevice/Provisioning Profiles`.

### Checks after each build

- **ipa:** one app in `Payload/`; `CFBundleIdentifier` = `com.nickpopov.bookfetch`; `CFBundleShortVersionString`
  and `CFBundleVersion` equal `version.json`; `ITSAppUsesNonExemptEncryption` = `false` (the app uses only OS
  crypto: HTTPS and the Keychain); `main.jsbundle` is present (a Release build with the embedded bundle).
- **Merged release manifest:** `package` = `com.nickpopov.bookfetch`; `versionCode`/`versionName` equal
  `version.json`; `android:usesCleartextTraffic="true"` (LAN servers at `http://192.168.x.x` must work); the
  `INTERNET` permission. The lane prints the full permission list. It fails only on location, camera, contacts,
  microphone, SMS or phone permissions; entries with `tools:node="remove"` don't count.

## Versions and build numbers

- `version.json` (`{ "version": "1.0.0", "build": 1 }`) is the source of truth. The app config maps
  `version` → `version` (iOS `CFBundleShortVersionString`, Android `versionName`), and `build` →
  `ios.buildNumber` (as a string) and `android.versionCode`.
- One build counter serves both platforms and must rise with every store upload. The `beta` lanes compute
  the next value from the store and write it with `scripts/bump-version.mjs --build N`, leaving the change in
  the working tree. **Commit `version.json` after an upload.**
- `node scripts/bump-version.mjs` raises `build` by one. `--version X.Y.Z` and/or `--build N` set the values
  instead, and `--version` alone keeps `build`. Bad input exits 1 without writing.
- A new marketing version (for example 1.0.1) needs `bump version:1.0.1`. The build number keeps rising and never resets.

## Store rules to remember

- **App Store Connect:** create the app record for `com.nickpopov.bookfetch` before the first `ios beta`.
  Export compliance is answered by `ITSAppUsesNonExemptEncryption = false`. Submitting for review (metadata,
  screenshots, privacy answers: no data collected) happens in App Store Connect after the TestFlight build is processed.
- **Google Play, first upload:** create the app in the Play Console first. Until the app's first release has been
  rolled out from the Console, the Publishing API accepts only **draft** releases, so `android beta` defaults to
  `status: draft`. Finish that first release by hand in the Console (internal testing → review the draft → roll
  out). After that, `status:completed` publishes straight to internal testers.
- **Production access on a personal Play account:** a developer account created as a personal account after
  November 2023 must run a **closed test with at least 12 testers opted in for 14 continuous days** before it can
  apply for production access. Internal testing does not count toward this. Plan the closed track early: the
  internal-track draft tonight is only the first step.
- Signing: Play App Signing holds the app signing key, and the keystore in `ANDROID_UPLOAD_*` is the upload key.
  If the upload key is lost, reset it through Play Console support.
